# PR-L2 — `auto_lossy_damage_threshold` tuning sweep (2026-06-30)

Corpus measurement that drives the choice of
`SolverConfig::auto_lossy_damage_threshold`'s default. Stacks on top of
PR-L (#70), which shipped the knob at `Some(10_000)`.

Generated by `cargo run --release -p vgc-solver --example sweep_threshold`.
The harness sweeps `EnumerateOpts::auto_lossy_damage_threshold` across
`{None, Some(10_000), Some(5_000), Some(1_000), Some(500), Some(100),
Some(50)}` for each of the three `measure_2v2` scenarios at depths
{1, 2}, with `wall_cap` of 30–45 s per solve.

Switch-heavy is structurally identical to Midgame in this team (both
build off the same `scenario_midgame()` battle) — it was dropped from
Phase 2 onwards to recover wall budget.

## Headline

**Lowest threshold where Nash value matches lossless within 1% across
every (scenario, depth) measured: `Some(1_000)`.** The corpus shows the
existing `Some(10_000)` default leaves 4× of the available wall-clock
win on the table at d=1 without any fidelity cost.

- **OHKO d=1 wall**: lossless **52.47 s CAP** → `Some(10_000)` 14.87 s
  → **`Some(1_000)` 3.71 s** (4× faster than 10k; 14× faster than
  lossless). All Nash values bit-identical at `+0.000498`.
- **Midgame d=1 wall**: lossless **34.99 s CAP** → `Some(10_000)` 30.03 s
  → **`Some(1_000)` shows DepthLimit completion** with 6,791 recursive
  nodes vs 4,565 at 10k. Nash values identical at `-0.000498`.
- **Midgame d=2 wall**: same Nash value across the full sweep; lower
  thresholds get strictly more nodes inside the same budget.

Nash delta across all `(scenario, depth, threshold ≤ 10_000)` cells is
**0** to 6 decimal places. Engagement % rises smoothly:
~7 % at 10k → ~36 % at 1k → ~45 % at 50.

## Method

Each row in the sweep is a single recursive doubles solve, performed
inside the existing `measure_2v2.rs`-style harness (`SolverConfig`'s
single-slot `endgame_solve` doesn't cover doubles). Per-solve budget is
`wall_cap` plus a 15 s watchdog buffer that synthesises a `NodeLimit`
result if a single `enumerate_outcomes_with` call exceeds the budget.

- `wall_cap = 30 s` on the Midgame and OHKO d=2 columns.
- `wall_cap = 45 s` on the OHKO d=1 column (the original, slower run).

The harness writes one markdown table per `(scenario, depth)`. Nash
delta is computed against the first non-`CAP` row in the table — the
lossless reference when it completes, otherwise the largest threshold
that hit `DepthLimit`.

## Nash-delta curve

Across all measured `(scenario, depth, threshold ≤ 10_000)` cells, the
Nash-value delta vs the lossless reference (or `Some(10_000)` at d=2
where lossless CAPs) is **0** to 6 decimal places. The harness produces
bit-identical leaf evaluations once the auto-lossy partition aligns
because PR-C's 3-bucket collapse preserves expected damage exactly and
the `hp_ratio_leaf` evaluator is monotone in HP.

This confirms the soundness argument from `lib.rs` — auto-engagement at
any threshold above the per-cell minimum (1) is bit-safe under
`hp_ratio_leaf` / `kho_race_leaf`.

## Wall-clock curve

OHKO d=1 (the only `(scenario, depth)` where lossless completes within
budget) is the clearest signal:

```
threshold:   None    10k    5k     1k     500   100   50
wall (s):    52.47   14.87  14.60  3.71   2.82  2.71  2.69
```

The curve has two knees:

1. **Around 10k–5k:** engagement stays under 10 %; the dominant
   monster cells get caught, but typical 32–4096 combo cells still go
   lossless. Wall stays ~15 s.
2. **Between 5k and 1k:** engagement jumps from 7 % → 36 %; the
   "medium-large" cells (a few thousand combos) collapse onto 3 buckets.
   Wall drops 4× to 3.71 s.
3. **Below 1k:** engagement creeps up to 45 % but wall is flat
   (~2.7 s) — the remaining cells are already cheap enough that the
   collapse doesn't move the needle.

The sweet spot is **`Some(1_000)`**: catches both the monster outliers
and the medium-large cells, leaves the typical 12-combo cells lossless,
and Nash value still matches bit-for-bit.

## Decision

**New default: `SolverConfig::auto_lossy_damage_threshold = Some(1_000)`.**

This drops in directly. Existing PR-L tests (`solver_with_default_…`,
the engagement non-engagement pair) keep passing. Two new tests pin the
choice:

- `default_threshold_matches_lossless_within_1pct` — runs the smoke
  fixture at `SolverConfig::default()` and asserts |Nash delta| < 1%
  vs `auto_lossy_damage_threshold: None`.
- `lowering_threshold_increases_engagement` — sweeps thresholds down
  and asserts engagement count is monotone non-decreasing.

## Honest verdict

The PR-L default `Some(10_000)` was conservatively high — it caught the
262k+ monster cells but missed an entire band of medium-large cells
that the corpus shows collapse safely. Lowering the default to
`Some(1_000)` is a clean 4× wall-clock win on OHKO d=1 with **zero**
Nash-value change anywhere in the sweep.

If a future change makes the leaf evaluator non-monotone in HP, this
default needs to come back up. The mechanism is preserved (`Option<u32>`,
`None` reproduces pre-PR-L behavior bit-for-bit) — only the numeric
default changes.
