# Lossy fidelity audit — 2-ACTIVE revisit (2026-07-09)

Companion + **correction** to `lossy-fidelity-audit-2026-07-01.md`. That
audit concluded the lossy damage-collapse configs had **"0 % Nash delta /
100 % top-1 policy match"** vs lossless, and declared them "safe for
best-move recommendations." This revisit shows those conclusions were
artifacts of the original audit's fixture construction and **do not hold on
genuine 2-active doubles states** for the *forced* 3-bucket collapse.

Generated by
`cargo run --release -p vgc-solver --example lossy_fidelity_2active`.

## Why the original audit was compromised

Two problems, both discovered while wiring up this revisit:

1. **Buggy `ko_split` baseline.** The 2026-07-01 audit's "lossless `None`"
   reference used the pre-#87 `ko_split` survivor-pinning, which silently
   dropped reachable frontier states (fixed in #87). Its "lossless" ground
   truth was itself lossy.

2. **1v1-active fixtures (the structural blind spot).** *Every* fixture in
   the original audit — both §1 corpus and §2 adversarial — **fainted
   slot-1 on both sides** (`lossy_fidelity_audit.rs` lines 672–688:
   `b.p1.team[1].current_hp = 0; b.p2.team[1].current_hp = 0`). That
   reduces each position to a **single live defender per side**. With only
   one defender there is no *target choice*, so the **mutual-focus
   coupling** that dominates real doubles — "do both my attackers focus one
   foe, or split across two?" — **cannot appear in the action space at
   all.** The §2 "adversarial bucket-boundary" fixtures were adversarial
   for the *arithmetic* of one hit, but structurally blind to the *policy
   coupling* the collapse actually distorts.

The 3-bucket collapse preserves expected damage but **not** the post-hit HP
distribution — survivors land on one of 3 representative HP values instead
of up to 16. In a 1v1-active state a survivor's exact HP rarely changes the
single available action. In a 2-active state, that survivor's HP feeds the
*joint* target-selection payoff — and that is where the collapse bites.

## Methodology (2-active)

- **Fixtures:** 6 genuine 2-active doubles positions — **both slots alive on
  both sides**. Distinct-speed, low-bulk, single-strong-move attackers so
  the tree solves to `Exact`/`DepthLimit` within the wall cap while sitting
  near KO thresholds (where the bucket collapse is worst). Teams are
  Reg M-B-faithful: **Tera is latched spent** (`tera_used = true`) on both
  sides so no format-illegal `Terastallize` action inflates the frontier.
- **Configs solved per fixture:**
  - **(a) lossless** — `EnumerateOpts::default()` = 16 hp_bucket segments,
    no auto-collapse. This is the post-#87 sound default.
  - **(b) auto(1000)** — `auto_lossy_damage_threshold = Some(1_000)`, the
    current `SolverConfig` production default. Engages the 3-bucket collapse
    only on cells whose lossless draw tensor exceeds 1000.
  - **(c) 3bucket** — `lossy_damage_3bucket = true`, forces the {0,7,15}
    collapse on **every** damaging cell.
- **Measured per config vs lossless (a):** Nash-value delta, root **top-1
  joint action** agreement, and support-set agreement.
- **Aggregate rule:** only count a comparison when **both** the lossless
  reference and the row completed non-CAP (`Estimated::NodeLimit`
  excluded). Comparing a CAPed lossless value against a completed lossy
  value is apples-to-oranges and would fabricate a delta.
- Depth 1 and depth 2, seed `0xC0DE`, `hp_ratio_leaf`.

### The D01 policy flip (root cause)

`PROBE=0 DEPTH=1` dumps the full root policy support for D01. Both lossy
and lossless agree the Nash **value** is `+0.900000`, but the recommended
**joint action** differs:

```
--- lossless  | val=+0.900000 ---
  1.0000  [Weavile→P2 slot0 | Gengar→P2 slot1]      # SPREAD across both foes

--- auto(1000)| val=+0.900000 ---
  1.0000  [Weavile→P2 slot0 | Gengar→P2 slot1]      # SPREAD (matches lossless)

--- 3bucket   | val=+0.900000 ---
  1.0000  [Weavile→P2 slot0 | Gengar→P2 slot0]      # DOUBLE-FOCUS one foe
```

This is a **pure-strategy top-1 disagreement** (support size 1 both sides,
not a mixed-strategy tie): the forced 3-bucket collapse tells the solver to
**double-focus P2 slot 0**, while the sound engine tells it to **spread
across both defenders**. This is precisely the mutual-focus target-coupling
the 1v1-active 2026-07-01 corpus could not represent — with one defender
there is no slot-0-vs-slot-1 choice to get wrong.

Why identical Nash value with a different action? At the root, both
allocations clear the same amount of expected value against a best-
responding opponent; the collapse's per-hit HP distortion shifts *which*
allocation is (weakly) optimal without moving the game value. A best-move
recommender consuming the 3-bucket policy would surface the **wrong target
allocation** to the player while displaying an unchanged win-probability.

## Auto(1000) survives — and why

`auto(1000)` matches lossless **bit-for-bit on all 6 fixtures** (dNash = 0
wherever both completed, including D01). The reason is mechanical: these
small endgame cells never exceed the 1000-entry draw-tensor threshold, so
**auto never engages the collapse** and stays identical to lossless. The
default is safe here *because it declines to collapse* — not because the
collapse is harmless. The moment a cell is large enough to trip the
threshold (the long-tail spread-move × secondary-chain cells the threshold
exists to tame), it applies the **same** `lossy_damage_3bucket` transform
that flipped D01, and inherits the same policy-distortion risk on any
2-active coupling inside that cell.

## Verdict — how wrong was the old "0 % delta"?

- **Old claim:** "0 / 12 top-1 disagreements even on adversarial fixtures;
  safe for best-move recommendations." → **Overturned for the forced
  3-bucket collapse.** On genuine 2-active states it produces a **real
  root-policy flip (D01, depth 1)** at identical Nash value. The "100 %
  top-1 match" was an artifact of 1v1-active fixtures with no target choice
  to disagree about.
- **Nash-value delta:** the old "0 % Nash delta" headline is **literally
  true and simultaneously misleading** — Nash *value* is preserved (max
  |dNash| = 0.000000 across every valid 2-active comparison) while the
  *policy* is not. Value-parity is the wrong safety metric for a best-move
  recommender or a policy-target self-play pipeline; **top-1 / support
  parity is.**
- **auto(1000) default:** holds up on this corpus (4/4 top-1 at both
  depths) — but only because it doesn't engage on cells this small. Its
  safety is a threshold-coverage property, not a collapse-soundness
  property.

### Superseded conclusions from `lossy-fidelity-audit-2026-07-01.md`

- §1 "top-1 agreement … 21/21 = 100.00 %" and §2 "0 / 12 top-1
  disagreements" — **superseded.** Both measured only 1v1-active states and
  cannot speak to 2-active target coupling. The forced 3-bucket collapse
  disagrees on top-1 in a 2-active state (D01, depth 1).
- §3 "Consumer applications … Safe. The top-1 root action is invariant" —
  **superseded for `lossy_damage_3bucket = true`.** Not invariant on
  2-active states.
- §3 "Self-play training data generation … Safe … Zero support-set drift" —
  **superseded for the forced collapse.** D01 shows support-set drift
  (spread vs double-focus) — a self-play pipeline labelling policy targets
  from the 3-bucket solver would embed the wrong target allocation.
- The `auto(1000)` **value**-parity claims stand on this corpus, with the
  caveat above that the parity is a threshold-coverage artifact, not
  evidence the underlying collapse is policy-sound.

## Caveats

1. Corpus is 6 fixtures (4 with valid both-completed comparisons per
   depth). This is a **strong negative result** — one clean 2-active
   counterexample (D01) is sufficient to overturn the "always 100 %" claim
   — not a distribution-wide bound on *how often* the flip occurs.
2. D03/D06's lossless reference CAPs (deeper mixed-team trees exceed the
   wall cap even to `DepthLimit`). Their lossy-vs-lossless rows are
   correctly excluded; the large apparent deltas there are truncated-search
   artifacts, not fidelity measurements.
3. The engine's `chance.rs` (real play) always uses 16 buckets; this audit
   is strictly about the **solver's** enumeration approximation.

## Reproducing

```
cargo run --release -p vgc-solver --example lossy_fidelity_2active
```

Environment knobs:

- `DEPTH=1|2` — search depth (default 2).
- `WALL_CAP=<secs>` — per-solve wall cap (default 60).
- `AUTO_THR=<N>` — auto_lossy threshold under test (default 1000).
- `PROBE=<idx>` — dump full root policy for one fixture across all 3 configs
  (e.g. `PROBE=0 DEPTH=1` reproduces the D01 flip above).
