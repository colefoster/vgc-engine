# vgc-engine

A from-scratch, data-oriented Pokémon battle simulator in Rust. Goal: what `pkmn/engine` is for gens 1–2 singles, but spanning modern competitive play — **gen 9 doubles first**, earlier gens added incrementally as data overlays. Zero-allocation hot loop, integer-id dispatch, bit-packed state, exposed to Python via `pyo3` so ML pipelines (the sibling `~/Dev/mimikyu` repo) can drive millions of rollouts/sec. **Pokémon Showdown (PS) is the correctness oracle** but is 400–1000× too slow for deep search. The concrete target format is **Pokémon Champions, Regulation M/B doubles** (see Format scope below).

This file is the durable working context; root `CLAUDE.md` imports it, so Claude Code loads it automatically. Also read `docs/AGENTS.md` (the contributor rulebook) and `docs/DESIGN.md` before writing code. `README.md` and `docs/PLAN.md` have the pitch/roadmap.

## Architecture / key components

- **Workspace crates** (`crates/`): `vgc-engine-core` (the sim — `battle.rs` is ~21k lines and the heart), `vgc-engine-data` (build.rs codegen from the `~/Dev/localdex` JSON dump), `vgc-engine-cli` (`vgc` binary + calc/score-corpus subcommands), `vgc-engine-golden` (goldens + perf benches + calc-oracle suite), `vgc-engine-conformance` (PS-vs-engine differential), `vgc-engine-replay`, `vgc-solver` (matrix-game/endgame solver), `vgc-engine-calc-oracle-web` (local damage-calc webui), `vgc-engine-py` (pyo3 wheel, built via maturin — excluded from default `cargo build`).
- **Core src** (`crates/vgc-engine-core/src/`): `battle.rs`, `damage.rs`, `damage_api.rs`, `calc.rs`, `ability.rs`, `item.rs`, `pokemon.rs`, `order.rs`, `rng.rs`, `chance.rs`, `canonical_hash.rs`, `step_machine.rs`, `format_rules.rs`, `team.rs`, `team_export.rs`.
- **Perf architecture (do NOT regress):**
  - **Integer-id dispatch, never string slugs, in hot paths.** `build.rs` generates `ability_id::*` / `item_id::*` / `move_id::*` / `species_id::*` const modules. Compare `effective_ability_id() == ability_id::INTIMIDATE`, not `slug == "intimidate"`. Only legit slug uses: species prefix matches (`starts_with("ogerpon")`) and a few helper internals.
  - **`step()` is heap-free (hard rule).** No `Vec`/`Box`/`String`/`format!`/`collect` in the `step()` call tree. `action_order` uses a fixed `[ScheduledAction; 8]`; `enumerate_targets` returns a fixed `TargetBuf`; damage passes 12-byte `FinalStats` snapshots, not 40-field `Pokemon` clones; `VolatileSet` has a `u64 present` bitmask. Construct mons via `Pokemon::with_identity(...)`, never raw struct literals (a new field breaks ~6 sites otherwise).
  - **Damage formula is calc-oracle-exact** and enforced on every test run — do not "fix" it to move any metric.
- **The `damage_only(&DamageQuery) -> [u16;16]` API** (`damage_api.rs`) is the pure damage primitive (synthetic 1v1, 16-roll enum, no Battle turn/EOT). It backs the `vgc calc` CLI, the calc-oracle, and any external consumer. `vgc-solver` exposes `endgame_solve` / `step_chance` and a pyo3 `solve_endgame` binding (batched leaf evaluator, latest work).

## Conventions & how the user wants you to work

- **Autonomous PR-stream mode is authorized for vgc-engine.** Default to: implement → test → clippy → commit → push focused PRs straight to `main`, no per-PR "ready to continue?" check-ins. Surface a checkpoint only for load-bearing structural decisions (new module org, breaking API change, abandoning a documented approach). This is pre-alpha foundational work with one human in the loop; friction is the enemy. (Does NOT generalize to other repos.)
- **One mechanic per PR.** A mechanic = one move / ability / item / structural change. Bundling defeats differential attribution.
- **Cite sources in commit messages** — PS `file:line` + Bulbapedia URL. Log source disagreements in `docs/known_divergences.md`. **Match PS where PS disagrees with the cartridge** (mimikyu's corpus is PS replays; cartridge-faithful behavior is a non-goal).
- **For Champions, match the REAL researched game, not just whatever PS does.** Champions' damage FORMULA is mainline gen-9 byte-identical; every Champions difference is DATA in the PS champions mod. Distinguish formula (already correct) from data deltas (the real bugs). Trace a reported bug to a from-scratch repro before "fixing" — misdiagnoses are common (an "Excadrill does 0 damage" bug was actually a foe's flinch chance). Off-by-1 rounding is a low-value rabbit hole; high-impact data/mechanic gaps are the prize.
- **Don't chase bit-exact RNG draw-parity.** Fix missing/wrong MECHANICS the harness surfaces; do NOT add/remove no-op RNG draws to byte-align the LCG stream. The user has stopped agents for this. The corpus/OracleKeyed OUTCOME comparison is the real signal, not draw-count.
- **Verify before reporting done.** Don't call a fix "done" while it only lives on an unmerged branch — the user tests `main` and will say "still not fixed." Either merge it or state "fixed on PR #N, not on main yet." For invisible-by-design fixes, prove it with a `main`-vs-branch A/B.
- **Distrust subagent estimates and "all green."** Perf self-time %, mechanic battle-counts, and "it's noise" all run optimistic — confirm perf with best-of-N interleaved A/B wall-clock and mechanics with the real corpus clean-count delta. Grep-verify every "X is missing" claim against engine source before implementing. Before quiet-listing a failing scenario as a "harness confound," do the delta arithmetic against known tick sizes (sand/burn/grassy = max_hp/16) — irregular deltas mean a real bug.
- **When a subagent proposes 3+ designs in one message without writing/testing code, it's spiraling — stop it and restart with a tighter brief.** Don't re-litigate decisions the user already parked (e.g. accept the synth-score cap, don't chase RNG parity); flag it and ask instead of enthusiastically designing around it. Lead with the honest weakness of an approach, not the optimistic case.
- **For a mechanic with known interaction edges, research first, implement second** — read PS source + Bulbapedia, document findings in `docs/interactions.md` (the authoritative 787-line gen-9 edge-case reference; grep it before adding any mechanic), then implement.
- **Solver collapse/factoring soundness:** green bit-exact tests never prove soundness. Adversarially hunt what the eligibility gate must bail on but might not (status-gated non-participation, joint/faint-before-acting coupling, KO-triggered abilities, HP-threshold triggers, redirection/spread). Prefer BLUNT deny-by-default gates over surgical predicates. Run an independent review pass whose sole job is finding the missing gate case — it has paid off every single time. Nash *value* parity is the WRONG safety metric; check top-1/policy agreement.

## Gotchas / things that have bitten us

- **Gap-doc "shipped/missing" counts are repeatedly WRONG and go stale within hours.** `docs/gaps/*.md` are valuable as citation catalogs (PS file:line + hook pointers are stable) but useless as progress trackers. Before implementing/claiming a mechanic is missing, grep source for a real behavioral arm. **Grep the string slug too, not just the `::` symbol** — many mechanics dispatch via string-literal match arms (Scope Lens, King's Rock, Razor Fang) and a symbol-only grep misses them. A slug appearing only inside a golden-team JSON is NOT an implementation. An id existing in a data table does NOT mean the mechanic is wired (Fur Coat / Analytic / Rivalry / Stench were all unwired despite having ids).
- **The engine HAS a working PP system** (populated from move data, decremented, gates selection at 0 PP). The old "no PP system" claim was false and wrongly blocked Pressure/Leppa/PP-Up work — all shipped.
- **PS draws RNG unconditionally, then vetoes AFTER via onTry hooks.** When refactoring accuracy/secondary/contact-ability code, leave the veto predicates (Shield Dust, Covert Cloak, status immunity, Safeguard, Inner Focus) INSIDE the draw site. Moving a veto ahead of the draw changes the draw count for the failed case and silently breaks the conformance harness while lib tests (which assert final state, not draw count) stay green.
- **Status moves that DRAW must set RNG move-context explicitly.** They don't pass through the damaging-hit loop that calls `set_move_context`, so their draws inherit the prior action's stale key. Call `self.rng.set_move_context(...)` + `set_decision(...)` before drawing (a no-op for non-OracleKeyed RNG).
- **Champions data-delta trap:** always grep `data/mods/champions/moves.ts` before changing any move's chance/secondary/BP. Freeze-Dry, Powder Snow, Make It Rain (-2 not -1), Salt Cure (1/16 not 1/8), Iron Head flinch (20% not 30%), Moonblast/Dire Claw chances all differ. Many "overrides" are just `isNonstandard` bans, not combat rebalances.
- **`ResidualIndex` hygiene:** when you mutate a field the index tracks (status, item, volatiles, weather, terrain), keep it in sync — use the canonical setters (`try_set_status_from_src`, `set_item_from`, `set_weather`) or call the family sync helper within ~6 lines. Run `bash tools/audit-residual-index/audit.sh` before a PR. For scratch mons not installed in a Battle slot, add a `// AUDIT-OK: <reason>` comment.
- **Multi-hit: PS re-rolls crit AND the 85–100 damage randomizer every strike.** The OracleKeyed RngKey has no hit index, so per-hit draws are a FIFO queue per key — an under-drawing engine (one roll reused across hits) shows "0 unmatched" while diverging. Draw per-hit to consume PS's queued values in order.
- **Champions replaced EV/IV with Stat Points.** Teams use 0–32 SP/stat (66 total budget); the bridge is `EV = 8·sp − 4`, exact at Lv50/IV31. IVs standardized at 31 (no 0-Atk sets). Conformance/calc-oracle teams must be valid Champions Stat-Point teams, not 252-EV.
- **Multi-PR sessions: work in a dedicated git worktree.** Something in the local environment (sibling agents/tooling) periodically runs `git checkout` on the shared `~/Dev/vgc-engine` checkout mid-session, reverting uncommitted edits. Commit immediately after each step so a revert can't destroy work; don't mutate the primary checkout (checkout/rebase/merge) while other work is in flight — do merges in a throwaway detached worktree. After any committing agent, verify the push landed: `git ls-remote origin main; git rev-parse HEAD` must match.
- **Stacked-PR merge caution:** squash-merging a stacked chain to main breaks children (squash SHAs diverge from stacked bases). Rebase each child `--onto main <original-parent-SHA>` before merging; don't blind-loop `gh pr merge` over a stack.
- **Conformance punch-list `out_NN` indices are stale** — they reference an ephemeral `/tmp/conf-batch` batch; after regen, `out_NN` is a different battle. Implement the MECHANIC the entry describes; don't trust the index to reproduce it.
- **Patch the RECORDER, never the ROLLER.** When conformance draws mismatch you may patch how the local PS build records/labels its draws (gameplay-neutral, PS stays oracle); you must NEVER patch PS's roll values/order. The real levers are decision-LABEL alignment (fix in the recorder/`event_for_draw`) and draw-COUNT matching (a real engine mechanic-shape fix). A latent gap: bool-valued `range` draws (e.g. Fickle Beam's chance gate) get silently dropped by `as_u64()` — decode via `as_bool()`.

## Correctness signals (four orthogonal oracles)

Each catches a different bug class; run the relevant one for the change.
1. **calc-oracle** (highest quality, independent of PS entirely) — `cargo test -p vgc-engine-golden --test calc_oracle_suite --release`. Validates engine damage against `@smogon/calc` via the pure `damage_only` API (167 scenarios). Browse/re-run at `cargo run -p vgc-engine-calc-oracle-web` (127.0.0.1:8787). Scenarios in `tools/calc-oracle/`; `KNOWN_FAILURES` in `calc_cache.rs` inverts (fails if a listed scenario starts passing). Hard rule for scenarios: defender holds NO item and uses Splash.
2. **conformance / breadth corpus** (the mechanic-finder) — drive PS-recorded battles, replay into the engine under `Rng::OracleKeyed` (keyed by `(turn,actor,target,move,decision)`, not LCG position); state divergence with `0 unmatched draws` = real mechanic bug. Drive the Champions mod (format id **`gen9championsdoublescustomgame`**), never base gen9, or every Champions data delta shows as a false divergence. Scale via `tools/conformance-batch/{mkjobs.py,run-batch.js}` over the `regmb_random_*` team pools in `~/Dev/mimikyu/data/generated_teams/`. Triage with `cargo run -p vgc-engine-conformance -- --draw-report`. **Bucket BOTH `field X` and slot-based (`hp`/`ability`/`status`/`boosts`) divergences, filtered to turn-1-0-matched, for a clean signal.**
3. **distribution-test** (`tools/distribution-test/`) — 1000 trials, KS-test post-turn-1 HP distribution vs PS. Catches statistical/math bugs, independent of PS draw order.
4. **PsGen5** (`cargo run --release -p vgc-engine-golden --example explore -- --psgen5 <dir>`) — bit-exact PS Gen5 LCG. Currently PARKED as a mechanic-finder: its residual divergences all trace to the `order.rs` speed-tie ordering nonce (draw-alignment), not mechanics. Use the breadth corpus instead.

The strict `corpus_zero_divergences` golden gate is default-on for every workspace test run. Any PR touching `core/src/{battle,damage,ability,item,pokemon}.rs` must run `cargo test --workspace --exclude vgc-engine-py`.

## Format scope

- **Terastallization is BANNED in Reg M/B.** Tera is implemented but must NOT be enumerated by `legal_choices()` in this format; all Tera-specific mechanics (Tera Blast, Stellar) are out of scope for the accuracy goal.
- **Mega Evolution is LEGAL and important** — the roster is data-complete and mechanically correct (cross-gen mechanic added to the gen-9 core; resolves at PS order 104). Prioritize mega completeness.
- **Team legality is opt-in, not enforced in battle.** `format_rules.rs` has `verify_team` + a `parse_and_verify(team, format="regmb")` pyo3 entry point (Reg M-B rules, 208-species allowlist, learnset move-legality). Per the user's "trust the team" call, the engine trusts callers to supply legal sets at battle time.

## Current focus / open threads

- **The strategic line is settled: the solver is an ENDGAME tool; healthy midgame belongs to a learned evaluator.** Wide-2v2 midgame is information-theoretically irreducible pre-step — proven from 5 angles (coupling graph reverted for net regression; spread-move removal made it worse; interval-dominance pruning inert; pre-step dedup inapplicable; damage-based levers exhausted). Reachable solver depth ≈ `root_cells × damage-hits-per-turn`; competence lives in the ≤~32-cell depleted-endgame tail. Do NOT reach for another damage-based collapse lever.
- **The big shipped solver win is `canonical_hash` field-hashing** (PR #114): it was doing `serde_json::to_vec` every call (~77% of endgame cell wall-clock); direct field-hashing gave 7.5× on the hash / ~3.24× end-to-end, lossless, board- and depth-wide. Solver soundness is validated by `solver_accuracy_bench` (value-exact vs a fully-lossless independent reference) + `collapse_soundness` regression tests.
- **The active product pivot: mimikyu consuming solver endgame values as training labels.** The pyo3 `solve_endgame` binding (batched leaf evaluator) just landed. mimikyu does NOT consume the solver yet — it needs `Provenance::Exact/Terminal` labels on asymmetric ladder-replay endgames, generated offline in batch. The symmetric equal-speed mirror "floor case" (~128s) is a pathological microbenchmark, NOT the workload — deprioritized.
- **Mechanic completeness for Reg M-B is DEEP and the clean single-mechanic bug tier is exhausted on the current 100-team corpus.** Residual divergences are dominated by already-parked classes: action-derivation cascades (a different mon occupies a slot after an earlier switch/faint-order difference), Intimidate/Ditto-Imposter boost artifacts, and scattered base-damage rounding (Knock Off's ×1.5 is correct — its residual gap is a base-damage interaction, verified repeatedly). New clean wins need a fresh/larger/differently-shaped corpus, not a re-run.
- **Perf is ~445–1040× faster than PS per step, step() is 0-alloc, verified.** One-shot perf PRs on `resolve_move_with_pending` are wrung dry (~600ns target needs architectural work — undo-step API or per-Pokemon CoW, not helper extraction). When extracting helpers from the giant `resolve_move_with_pending` (~2434 lines) / `apply_single_hit`, default to `#[inline(always)]` — the auto-inliner won't reach across boundaries in fns that large and extraction otherwise regresses. `Battle::clone` is cheap (~48–59ns, ~11% of step) so CoW Battle is not worth it. Perf_bench's uniform random picker under-represents weather/status/multi-hit turns — trust interleaved A/B wall-clock, not flamegraph % for state-conditional code.
- **The outer `step()` resumability refactor** (for native chance-frontier branching, `docs/outer-step-refactor-design.md`) has F0–F3 shipped; **F4 (mid-loop resume inside the multi-hit loop) is the hard one and deserves a dedicated session.** The `PerTargetContext` from the completed damage-pipeline refactor is the captured-locals bundle it reuses. Escape hatch if F4 won't land: MCTS sampling against the v1 wrapper instead of native enumeration.
